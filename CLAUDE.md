# DJ Claude

This folder is a DJ rig that **you** (Claude) play. The user directs the set by typing here in Claude Code. The browser tab at http://localhost:4747 is just the sound system and visuals.

- Any message that sounds like a DJ instruction ("play X", "harder", "kill the bass", "mix into something darker", "get me some trance") is live direction: load the **dj** skill and act on it immediately with `node dj.mjs …`.
- "Play a set" / "DJ for me" / "take over" means the **dj-set** skill (autopilot you can steer).
- Before any `dj mix`, the **dj-mix** skill has the transition craft. Downloading and searching music is **dj-crate**. Recording the decks and rendering a video of a set is **dj-video**. Mashups are **dj-mashup**, speech clips as vocals **dj-voice**, a produced album **dj-album**, and anything broken **dj-troubleshoot**.
- During a live set, keep every `dj wait` at 60 s or less, because the user's messages only reach you between tool calls. Check for new user text after each tool call. The user's latest words beat your plan. Keep chat replies to one line per event.

## Layout
- `server.mjs`: HTTP server. Holds the library, relays commands to the browser engine, long-poll `wait`, crowd inbox, booth log.
- `dj.mjs`: CLI control surface (`node dj.mjs help`).
- `lib/banner.mjs`: the server's startup banner. One of its `ANIMATIONS` plays at random (`DJ_BANNER=<name>` picks one), then the equaliser follows the live deck's beat (`banner.loop` setting, `DJ_BANNER_LOOP=0`). Plain text when the output is not a terminal. Preview them with `node dj.mjs banner [name]`.
- Health: `GET /api/health` (JSON, one ok/warn/fail/off entry per system: fail = a required system is down, warn = an optional one has a fault, built by `lib/health.mjs`) and the page at `/health` (`public/health.html`). Checks run only on request. The DJ page asks once a minute while visible: the status light in its header (`setStatus` / `refreshHealth` in `public/ui/link.js`) turns amber on a warn, red on a fail, and links to `/health`.
- Visuals: the page at `/visuals` (`public/visuals.html` + `public/ui/visuals.js`), a full-screen WebGPU visualiser for a second screen; it only watches. The engine tab measures the master output (`public/worklets/visuals-tap.js`, fed by `public/ui/visuals-feed.js`, only while someone watches) and posts analysis frames; `lib/visuals.mjs` (`VisualsHub`) fans them out on `GET /api/visuals/events` with the "scene" (key, energy, structure of what is on the decks) and relays the optional audio (`GET /api/visuals/audio`, a WebM stream the engine tab encodes only while someone listens; `visuals.audio` setting). With `visuals.lowLatency` on, the sound goes tab to tab over WebRTC instead and the hub only passes signalling (`POST /api/visuals/rtc` from a viewer, `/api/visuals/rtc/engine` from the engine tab, `visualsRtc` events to the engine); `visuals.maxListeners` caps it and the relay is the fallback. `public/ui/visuals/sdp.js` makes the Opus line ask for stereo music. On the page: `public/ui/visuals/feed.js` (frames → one smooth signal, colours from key and deck), `stage.js` (three.js `WebGPURenderer`, shared uniforms, crossfade between two render targets, device-loss recovery), `morph.js` (the shared GPU elements that modes with a `morph()` shape, so a change between two of them is a morph and not a crossfade; the quality tiers low / medium / high, `?quality=`), `audio.js` (the sound, and `Sync`, which keeps measuring where the sound is against the frames so the picture stays locked to it), `modes/*.js` (one module per mode; the interface is at the top of `stage.js` and, for modes that morph, of `morph.js`; the names are also in `MODES` in `lib/visuals.mjs`). three.js is vendored in `public/vendor/three/` (see its README). `dj visuals [<mode>|auto]` (`cli-ext/visuals.mjs`). Unrelated to the offline `produce/viz.mjs`.
- Settings: the page at `/settings` (`public/settings.html` + `public/ui/settings.js`) edits config.json through `GET`/`POST /api/settings`; the page files the schema's groups under a few categories (`CATEGORIES` in `settings.js`), shows one at a time and has a search box. The schema, validation and which settings apply live vs after a restart are in `lib/settings.mjs` (its `ui.*` settings reach the DJ page in the `hello` and `ui` server events, into `ui` in `public/ui/state.js`); `applyLiveSettings()` in `server.mjs` pushes the live ones into the running objects.
- `public/engine.js` + `public/worklets/deck-player.js`: Web Audio engine. Four decks (C/D appear when loaded; A,C left / B,D right of the crossfader), key lock + key shift (WSOLA), per-stem playback (vocals/drums/bass/other), EQ/filter/echo, deck FX (reverb/flanger/phaser/gate/crush), 8-pad sampler, scratching, sample-accurate transitions. Engine CLI: `node dj.mjs help-engine`.
- `public/app.js`: UI boot + per-frame render loop; the rest of the UI is ES modules in `public/ui/` (`state.js` shared state, `link.js` server link + recorder, `commands.js` command handlers, `controls.js` knobs/buttons, `keys.js` chop keyboard + pads, `deck.js`, `layout.js` stacked/classic deck layout (`ui.deckLayout`) + the mixer's dB scale, `prefs.js` the `ui.*` settings on the page (localStorage copy, `saveUi`), `lower.js` the bottom panel: its tabs (Library, Sampler & keys, Booth: `ui.dockTab`, `ui.boothPinned`), hide and resize, `maximize.js` the panel maximised under a slim deck strip and the header's layout presets (Mix / Browse / Perform: `ui.layoutPreset`), `bindings.js` key bindings on the DJ page + the shortcut list (`settings-keys.js` is their editor on /settings; the actions are in `lib/keymap.mjs`, served as `/keymap.mjs`, presets in `lib/key-presets/`), `canvas.js` waveforms/jog wheels/meters, `turntable.js` the record player drawn in the jog wheel's place (`ui.deckStyle: turntable`: turning record, tonearm you can pick up to seek, hot cues as stickers), `hand.js` the scratch / nudge gestures shared by the jog wheel and the waveform, `wave.js` waveform gestures (drag to scratch, silent seek, nudge strip, zoom, double-click cue, the guard lock), `loader.js` loading a deck from the page + file import (`POST /api/upload`), `dragdrop.js` dragging rows and files onto decks (mouse and touch), `crate.js`, `booth.js`, `util.js`). `public/index.html`. Styles are per component in `public/css/` (load order in index.html matters). No build step.
- `lib/analyze.mjs`: BPM/beat grid, key (Camelot), energy, structure. `lib/library.mjs`: cache, search, suggestions. `lib/downloader.mjs`: yt-dlp wrapper.
- `lib/sequencer.mjs`: plan steps, track queue, auto-DJ. `lib/monitor.mjs`: mix monitor + transition critiques. `lib/memory.mjs` (.dj/memory.json), `lib/cues.mjs` (.dj/cues.json), `lib/sections.mjs`, `lib/music.mjs`, `lib/fx.mjs`, `lib/export.mjs`. Grid corrections: .dj/grid-edits.json.
- Tests: `node --test test/*.test.mjs test/server-*.mjs` (server tests run scratch copies on ports 4851-4858 with a fake engine and a generated library, `test/fixtures.mjs`: synthetic tracks run through the real analyser, cached in the temp folder; they never read or touch the real library or .dj/).
- Benchmarks: `node bench/<name>.bench.mjs` (`analyze`, `deck-voice`, `zoom`, `library`) runs the working tree against the git ref in `bench/baseline.json` (`BENCH_BASE=<ref>` overrides it) in one process and checks the output is byte-identical. Helpers in `bench/util.mjs`.
- `.dj/library.json`: analysis cache. `.dj/server.log`: server log. `bin/`: auto-installed yt-dlp.
- Stems: `lib/stems.mjs` + `lib/separate.py` (htdemucs in the project `.venv`) split every track into `.dj/stems/<id>/` in the background; vocal maps via `node dj.mjs vocals <id>`.
- CLI extensions live in `cli-ext/*.mjs` (engine, stems, …).
- `starter/tracks.json`: Creative Commons starter crate; `node dj.mjs starter` (`cli-ext/starter.mjs`) or the "Download demo tracks" button on an empty crate (`POST /api/starter`) downloads it into `library/starter/`; both use `lib/starter.mjs`. Credits and licences in `starter/README.md`.
- `produce/`: video production. `record-browser.mjs` (Playwright page recording that becomes the sound system), `make-video.mjs` (set audio → 720p/480p video with visualiser + DJ-table footage), `viz.mjs`, `get-sample.mjs` / `measure-sample.mjs` (short samples into `.dj/produce/samples/`), `index-captions.mjs` + `find-line.mjs` + `analyze-speech.mjs` (speech index in `.dj/voice/`), `build-reel.mjs` + `remix.mjs`/`chops.mjs` (voice reels), `run-design.mjs` (live design runner, times in `.dj/produce/out/run-design-times.json`), `album-design.mjs` + `songs/README.md` (album plans from `.dj/produce/beds.mjs` + `.dj/produce/songs/`), `cut-track.mjs`, `full-album.mjs`, `align.mjs`.
- Needs Node 20+ and ffmpeg/ffprobe on PATH. No npm dependencies.
